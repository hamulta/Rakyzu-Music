# Rakyzu Music Android 0.2.8

## Batched scope

This cumulative release delivers milestones `0.2.5` through `0.2.8` in one validated artifact, pipeline, tag, and release.

- `0.2.5`: derived ordered discovery categories from verified editorial shelves, added accessible category entry points, and preserved deterministic offline playback queues.
- `0.2.6`: added an authenticated, paginated full-catalog Supabase RPC with RLS-preserving `security invoker` execution, strict query/offset/page bounds, deterministic mixed-result ranking, publication filters, response validation, and Load more UI.
- `0.2.7`: added listener-isolated recent searches that are disabled by default, explicitly opt-in, capped at ten, encrypted with a dedicated Android Keystore AES-GCM key, and independently clearable.
- `0.2.8`: kept local results visible during remote loading/failure, cancelled stale request generations, exposed accessible offline/service status, and retried the last submitted search once when validated connectivity returns.

## Security and privacy

- Typing remains entirely local; only explicit submission sends a bounded query through the authenticated Supabase session.
- The search RPC runs as the caller, retains table RLS, denies anonymous execution, and returns only published catalog metadata.
- SQL parameters prevent injection; server-side bounds reject invalid queries, offsets, and page sizes.
- Recent searches are disabled by default and never persist until the listener opts in.
- Persisted history uses a separate private preference file, a dedicated non-exportable Android Keystore key, randomized AES-GCM encryption, hashed listener storage keys, bounded values, and account isolation.
- Disabling history removes stored queries; Clear history does not alter the current query or catalog.
- Queries are absent from logs, diagnostics, analytics, playback metadata, media requests, Worker requests, and R2 paths.
- No privileged Supabase, Cloudflare, R2, or GitHub credential enters the APK or tracked source.
