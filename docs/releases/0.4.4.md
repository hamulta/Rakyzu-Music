# Rakyzu Music 0.4.4 — cumulative 0.4.1–0.4.4

Android application ID `my.id.rakyzumusic`; versionCode `44`; Room schema `6`.
One cumulative distribution: `Rakyzu-Music-0.4.4-debug.apk`. No separate intermediate tags
or APKs are published for 0.4.1, 0.4.2 or 0.4.3.

## Included

- 0.4.1: playlist detail, durable account-scoped ordered snapshots, deterministic playback
  from all playable songs or a chosen row, with unavailable-song placeholders.
- 0.4.2: cached-catalog song picker and remove controls; server publication checks,
  duplicate prevention, correct counts and a 500-item limit.
- 0.4.3: immediate visual reorder via accessible up/down controls, serialized mutations,
  exact revision/permutation checks, rollback and conflict refresh without silent replay.
- 0.4.4: bounded/restorable metadata drafts tied to their original revision; private
  artwork upload/read/delete via authenticated Worker and R2; system photo picker,
  PNG re-encoding, bounded dimensions/bytes, full chunk/CRC validation and no EXIF or
  shared caching.

## Quality and release gates

See [WORK_SESSION.md](../WORK_SESSION.md) for the initial audit, persisted task checklist,
actual test evidence, CI/CD run IDs, release-download inspection and final handoff.
Android CI is consolidated into one Gradle invocation for unit tests, lint, debug and
instrumentation APKs, plus the release build. Playlist UI and Room migration runtime tests
run on the connected physical Android device. Reports are retained separately from the
distributable APK. No emulator or Appetize is used.

## Boundaries

- This remains a debug-signed development APK, not the signed production 1.0.0 release.
- List shows the most recent 100 playlists; song picker shows up to 50 matching cached
  catalog songs. Large-playlist pagination is scheduled for 0.4.8.
- Offline detail/playback metadata is retained; editing requires a successful refresh and
  online server acknowledgement. Durable playlist mutation outbox is scheduled for 0.4.7.
- Artwork uses last-successful-write-wins independently of playlist revisions. Offline
  artwork persistence, collaboration, ownership transfer and cover conflict resolution
  are not claimed in this batch.
- Runtime tests do not replace full physical-device, TalkBack, audio/network and production
  signing acceptance testing. The roadmap's dedicated hardening gate remains open.

Public design reference: [Spotify playlist concepts](https://developer.spotify.com/documentation/web-api/concepts/playlists)
informs ordered items and snapshot concurrency; implementation, assets and brand remain Rakyzu Music.
