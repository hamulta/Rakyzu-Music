# Rakyzu Music Android 0.1.0

## Scope

- Replaced the single catalog row with a data-driven Home feed containing recently played, server-curated editorial shelves, new releases, and the complete published catalog.
- Added two published editorial collections with deterministic track order and owned synthetic Rakyzu Music metadata.
- Added Media3 transition-based listening history so direct selection, previous/next navigation, queue selection, and automatic advance use one recording path.
- Persisted a maximum of 20 recent tracks per authenticated listener on the device and isolated history by Supabase user ID.
- Added Room schema version 2 with an automatic forward migration from version 1; catalog replacement does not destructively erase listener history.
- Validated all editorial identifiers, titles, subtitles, positions, membership, and uniqueness before replacing the last verified offline snapshot.
- Added published-only Supabase RLS and grants for editorial shelves and their track entries, including positive and negative pgTAP coverage.

## Security and privacy

- Anonymous users cannot read editorial metadata, and authenticated listeners cannot mutate it.
- An editorial entry is readable only while both its shelf and referenced catalog track are published.
- Recently played is device-local, bounded, account-isolated, and stores no token, media URL, R2 key, or privileged credential.
- A history event is discarded when its listener is signed out or its track is absent from the verified Room catalog.

## Quality gates

The release is accepted only after database migration replay, pgTAP policy tests, database lint and deployment; all Android unit tests; Android lint; Room schema generation; debug APK assembly; debug test APK assembly; minified R8 release assembly; manifest and signature verification; secret scanning; and final GitHub Actions success. The GitHub Release asset must exactly match the final CI artifact before tagging `v0.1.0`.
