# Rakyzu Music Android 0.2.4

## Scope

- Added a shared, local-only track context sheet to Search, artist detail, and album detail.
- Presented track artist, album, duration, disc, track number, and explicit-content metadata from the verified Room catalog.
- Added queue-aware Play track and capability-gated View artist and View album actions.
- Required both a surface callback and a non-blank canonical catalog ID before exposing either metadata-navigation action.
- Reused matching nested artist or album destinations instead of adding duplicate back-stack entries.
- Added explicit accessible labels and minimum touch targets for More, Close, playback, and metadata-navigation actions.
- Added five unit regressions and seven Compose accessibility/interaction regressions for capability filtering, navigation reuse, sheet content, and entry points.

## Security and privacy

- The context sheet reads only the already-observed local catalog and issues no network, Supabase, Worker, or R2 request.
- Artist and album navigation uses canonical catalog IDs rather than display-name inference.
- Track context adds no share intent, clipboard access, browser handoff, external URI, catalog mutation, or persistence path.
- Track IDs and metadata are not added to logs, diagnostics, analytics, or telemetry.
- Playback continues to cross the authenticated media boundary using only an internal track ID.
- No database migration, Worker deployment, Supabase policy, R2 object, Room schema, Android permission, or privileged client credential was added.
- Existing encrypted sessions, Supabase RLS, authenticated private media delivery, and cleartext-traffic rejection remain unchanged.
