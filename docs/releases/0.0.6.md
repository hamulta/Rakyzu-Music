# Rakyzu Music Android 0.0.6

## Scope

- Added authenticated, published-only Supabase catalog tables for artists, albums, and tracks.
- Added forced Row Level Security, explicit grants, relationship constraints, synthetic Rakyzu-owned fixtures, and pgTAP schema/policy coverage.
- Added the `core:database` module with Room 3, Android SQLite driver, transactional catalog replacement, Flow invalidation, and checked-in schema version 1.
- Added a catalog domain model and an offline-first repository that treats Room as the observable source of truth.
- Added bounded Supabase metadata queries and payload validation before any local replacement.
- Preserved the last verified catalog after network, service, or payload failures.
- Replaced hard-coded Home shelf entries with Room-backed catalog tracks and added lifecycle-aware loading, saved-catalog, error, and retry states.
- Kept media URLs, Cloudflare/R2 credentials, and privileged catalog mutations outside the Android client.

## Backend configuration

- Migration `20260829010000_catalog_foundation.sql` is forward-only and deployed after isolated pgTAP, lint, migration replay, and linked dry-run gates.
- The authenticated role can select only published metadata and cannot insert, update, or delete catalog rows.
- Audio delivery is intentionally deferred to the authenticated Worker/R2 contract in `0.0.7`.

## Quality gates

The release is accepted only after database pgTAP/lint/replay/deploy, all Android unit tests, Room query/schema generation, Android lint, debug APK assembly, and debug test APK assembly pass. The branded GitHub artifact and release asset must match this document before tagging `v0.0.6`.
