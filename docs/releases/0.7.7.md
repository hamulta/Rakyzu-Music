# Rakyzu Music Android 0.7.7

This cumulative `0.7.1`–`0.7.7` Android prerelease uses application ID
`my.id.rakyzumusic`, versionName `0.7.7`, versionCode `96`, and Room schema `11`.

## Track context

- The authenticated Worker returns only rights-aware lyrics and credits for a published,
  enforcement-available track. Territory mismatch yields an explicit unavailable state.
- Plain and synchronized lyrics include provider attribution, current-line focus, manual controls,
  large tap targets, and a fail-closed unavailable presentation.
- Primary Artist, featured Artist, songwriter, producer, and performer credits are normalized,
  source-attributed, role ordered, and bounded.
- Room stores complete context per account and track, replaces revisions transactionally, expires
  stale rights data, and removes cache entries for tracks absent from a successful catalog sync.

## Sharing and notifications

- Canonical track URIs contain only a public UUID. Inbound intents reject user info, query,
  fragment, nested path, and malformed IDs, then resolve only through the verified catalog.
- Android creates separate New music releases and Account and security notification channels.
  Android 13+ permission is requested only after an explicit opt-in.
- Release preferences are account scoped and server authoritative. Turning them off suppresses
  pending delivery records; clients cannot forge delivery evidence.

## Smart Recommendation

- The Made for you shelf ranks the verified local catalog from recent playback, Likes, saved
  albums, and followed Artists without transmitting a new behavior profile.
- Already consumed tracks are excluded, results are bounded and Artist diverse, signal-free
  accounts remain unpersonalized, and recommendations never alter the explicit playback queue.

## Public-configuration release correction — 2026-09-30

The first `v0.7.7` release asset was built locally without loading the three distributable public
values required by Android. The app correctly failed closed, but that made sign-in and sign-up
unavailable. The build now rejects every Android artifact before compilation when the hosted
Supabase HTTPS origin, non-privileged publishable key, or canonical Rakyzu API origin is missing or
malformed. Supabase secret/service-role keys are explicitly rejected.

The guard was exercised in both directions: a configuration-free build failed before APK creation,
while the configured cumulative gate passed unit tests, all module lint checks, debug and Android
test APK assembly, and the minified/resource-shrunk release build. A scan of the corrected APK
confirmed that all three public values are embedded; no privileged Cloudflare, R2, Supabase, or
GitHub credential is shipped.

The corrected APK was then run on an Appetize Pixel 9 Pro with Android 16. A newly created temporary
listener completed sign-up, confirmation, first-run profile creation, and reached Home; sign-out
returned to the sign-in screen; a second sign-in as that existing account returned directly to
Home. Neither UI inspection nor captured device logs contained the missing-configuration message,
Profile Unavailable, an authentication error, an application fatal exception, or an ANR. The
temporary Auth user, R2 transfer object, and Appetize build were deleted after verification.

The replacement debug APK is 29,699,292 bytes, identifies as `my.id.rakyzumusic` versionName
`0.7.7`/versionCode `96`, and has SHA-256
`84739ccfaf5a6fe2bb89020dd3447dae98ad255ca8c7fc499c8b55e31ff5a6a5`.
