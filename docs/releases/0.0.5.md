# Rakyzu Music Android 0.0.5

## Scope

- Added required display-name onboarding before the authenticated Android shell becomes available.
- Added owner-scoped profile loading and editing through Supabase Postgrest with existing Row Level Security.
- Added a forward-only `onboarding_completed` profile migration with pgTAP coverage for defaults, owner updates, and denied cross-owner updates.
- Added forgot-password email requests with a non-enumerating response and a dedicated branded PKCE callback.
- Added an encrypted password-recovery requirement that survives process death and clears only after a successful password update or local sign-out.
- Added profile loading, retry, onboarding, and account-editing state through a dedicated feature module and unidirectional ViewModel.
- Personalized the Home greeting using the validated listener display name and corrected the profile action target.

## Release identity

- Application ID: `my.id.rakyzumusic`
- Version code: `5`
- Version name: `0.0.5`
- Debug artifact: `Rakyzu-Music-0.0.5-debug.apk`

## Backend configuration

- Hosted and reproducible Auth configuration allowlists both `my.id.rakyzumusic://auth` and `my.id.rakyzumusic://auth/recovery`.
- Email confirmation remains mandatory.
- Passwords require at least eight characters with lowercase, uppercase, and a digit.
- Refresh-token rotation remains enabled with the ten-second reuse interval.
- The profile onboarding migration is deployed only after isolated pgTAP, lint, and migration replay succeed.

## Quality gates

The release is accepted only after database pgTAP/lint/replay/deploy, all Android unit tests, Android lint, debug APK assembly, debug test APK assembly, and recovery Android-test source compilation pass. Hosted Auth controls and GitHub release assets must match this document before tagging `v0.0.5`.
