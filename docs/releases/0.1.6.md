# Rakyzu Music Android 0.1.6

## Scope

- Added a validated Android connectivity monitor backed by the default-network callback without polling.
- Added bounded catalog retry delays of 1 second and 3 seconds, limiting each automatic refresh cycle to three requests.
- Restricted automatic retry to transient network and service failures; invalid catalog payloads fail immediately.
- Stopped pending backoff when connectivity is lost and retried immediately once a validated internet connection returns.
- Preserved duplicate-refresh coalescing and reset the bounded attempt budget only for a new manual or recovery cycle.
- Added an accessible waiting-for-connection state while retaining a 48dp manual Retry action.
- Added deterministic unit coverage for delay timing, retry exhaustion, manual recovery, invalid-payload handling, and connectivity restoration.

## Security and privacy

- The existing `ACCESS_NETWORK_STATE` manifest dependency is now explicit in `core:data`; no dangerous permission was added.
- Connectivity is reduced to an in-memory online/offline boolean and is never persisted, logged, or transmitted.
- Existing Supabase RLS, encrypted session storage, private R2 delivery, and account-isolated listening history remain unchanged.

The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.1.6`.
