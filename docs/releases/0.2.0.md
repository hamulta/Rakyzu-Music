# Rakyzu Music Android 0.2.0

## Scope

- Added the dedicated `feature:search` module and replaced the Search navigation placeholder with an executable offline-first surface.
- Added local artist, album, and track discovery over the canonical Room-backed catalog without a query-time network request.
- Added case-, whitespace-, and accent-insensitive matching with deterministic exact, prefix, token-prefix, contains, and association relevance.
- Preserved exact result totals while capping rendered results at 50 per type and guarding a generated 5,000-track catalog.
- Added explicit loading, browse, empty-catalog, no-results, and grouped-results states with polite live regions, headings, and minimum touch targets.
- Connected track results to Media3 queue playback using the displayed result order and selected index.
- Added 10 Search unit tests, Compose accessibility instrumentation coverage, and a dedicated GitHub Actions Search gate.
- Defined the Search release train from `0.2.1` through `0.2.10` before the Library milestone.

## Security and privacy

- Search input remains on-device for this milestone; it is not persisted, logged, sent to Supabase or the Worker, or included in diagnostics.
- Search reads only the authenticated listener's already-verified local catalog and introduces no privileged credential or direct R2 access.
- No database migration, Worker deployment, Supabase policy, R2 object, Room schema, Android permission, or telemetry was added.
- Existing encrypted sessions, Supabase RLS, authenticated private media delivery, and cleartext-traffic rejection remain unchanged.
- Large-catalog and accessibility fixtures use generated synthetic Rakyzu metadata only.

## Quality gates

The release is accepted only after 103 Android unit tests, Android lint with zero errors and no new warnings, focused Home and Search unit/lint/instrumentation-APK validation, debug APK assembly, all debug test APK assemblies, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. Instrumentation tests are compiled into their AndroidTest APKs; no emulator execution is claimed. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.2.0`.
