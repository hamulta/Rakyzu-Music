# Rakyzu Music Android 0.2.3

## Scope

- Added a typed album-detail destination reachable from Search album results and artist releases.
- Preserved the listener's Search query, selected Search destination, and prior nested destination across Back navigation.
- Derived album, artist, and track data entirely from the observed offline-first Room catalog using exact canonical IDs.
- Ordered the complete album queue by disc, track number, title, and ID with explicit multi-disc headings.
- Added Play album and accessible per-track playback actions using that deterministic queue.
- Added explicit loading, unavailable-album, and empty-album states.
- Added four album-detail state-holder tests, two navigation tests, and six Compose accessibility/interaction regressions.

## Security and privacy

- Album, artist, and track associations use canonical catalog IDs rather than display-name inference.
- Album detail reads the existing local catalog and issues no network, Supabase, Worker, or R2 request.
- Album IDs and catalog metadata are not added to logs, diagnostics, analytics, or telemetry.
- Media playback continues to pass only internal track IDs into the authenticated playback boundary.
- No database migration, Worker deployment, Supabase policy, R2 object, Room schema, Android permission, or privileged client credential was added.
- Existing encrypted sessions, Supabase RLS, authenticated private media delivery, and cleartext-traffic rejection remain unchanged.

## Quality gates

The release is accepted only after 117 Android unit tests, Android lint with zero errors and no new warnings, focused Home and Search unit/lint/instrumentation-APK validation, debug APK assembly, all debug test APK assemblies, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. Instrumentation tests are compiled into their AndroidTest APKs; no emulator execution is claimed. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.2.3`.
