# Rakyzu Music Android 0.5.30

This cumulative `0.5.26`–`0.5.30` prerelease uses application ID
`my.id.rakyzumusic`, versionName `0.5.30`, and hotfix versionCode `77`.

## Profile-context hotfix

- Decodes the scalar JSON object returned by `get_my_profile_context()` directly instead of using
  the SDK list-only `decodeSingle()` helper.
- Covers listener and verified staff payloads with regression tests, including nullable fields and
  forward-compatible response properties.

## Listener and authentication reliability

- Corrected the Android 16 cold-start race by moving repository-dependent work out of the
  `Application` constructor, initializing the repository graph deterministically, and deferring
  optional playback/background work until after `onCreate`.
- Corrected the profile RPC's nullable verification expression. Ordinary listeners now receive a
  real `false` Boolean, and a missing legacy profile row is safely repaired only for `auth.uid()`.
- Detects Supabase's empty-identity response for an already registered email and directs the user
  to sign-in or password recovery. Indeterminate confirmation responses use non-enumerating wording.

## Artist Studio and analytics

- Active Artist accounts can manage their own image, album artwork, viewer/editor team, album and
  track drafts, MP3/AAC/M4A/WebM/WAV/FLAC source audio, and independent review submissions.
- Artist tools never grant staff permissions or self-publication. Every mutation rechecks exact
  Artist/catalog scope on the server.
- The Studio shows a bounded 30-day stream/completion/follower/release view. Listener totals and
  geography are suppressed below five distinct listeners, and Android cannot write raw play rows.

## Commerce, account lifecycle, and Security Center

- The Worker verifies timestamped HMAC signatures before service-role play or commerce ingestion.
  Provider event IDs are idempotent; raw payload/customer references remain behind forced RLS.
- Authorized staff receive aggregate commerce metrics and masked account references. Entitlements,
  receipts, refunds, and disputes are derived from append-only provider evidence.
- Reasoned suspension/ban, listener appeals, reinstatement, and retention-aware deletion requests
  are exposed according to rank. Deletion requires two distinct executives and a 14-day cooling
  period; approval never immediately destroys data.
- Suspended or banned accounts lose effective Artist/staff permissions at the database helper
  boundary. Security alerts and protected-action evidence are visible only to authorized roles.

## Release gate

- Android validation passed 219 unit tests, all 14 lint reports, debug and instrumentation APK
  assembly, and the isolated R8/resource-shrunk release build.
- Worker validation passed 71 tests, both TypeScript checks, generated bindings, dry deployment,
  and production health at version `0.5.30`.
- PostgreSQL validation passed the isolated 316-test pgTAP replay plus schema lint; all three
  forward migrations are deployed and their production objects were verified.
- PR and main Android, database, and Worker CI/CD workflows completed successfully. The release
  APK is the exact main Android CI artifact.
- Appetize Android 16 kept the application process alive with `MainActivity` resumed, rendered the
