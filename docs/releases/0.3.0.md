# Rakyzu Music Android 0.3.0

## Scope

This release opens the Library milestone with a complete account-scoped foundation.

- Liked Songs, saved albums, and followed artists now share one offline-first Library surface.
- Search, track context, artist detail, and album detail expose authenticated Like, Save, and Follow actions with duplicate-request suppression and clear success/failure feedback.
- Liked Songs play as a deterministic Media3 queue; saved albums and followed artists open their existing typed detail destinations.
- Room schema 3 stores listener-isolated selections and synchronization metadata without destructive catalog coupling.
- Supabase stores canonical Library relationships behind forced RLS and `security invoker` projection/mutation functions, with pgTAP coverage for owner isolation, anonymous denial, invalid kinds, and unpublished content.
- The Android workflow now launches and exercises the authentication entry on a hardware-accelerated cloud Android emulator after static verification succeeds.

## Security and reliability

- Every remote Library row is listener-owned and isolated through forced Supabase RLS.
- Anonymous clients cannot execute Library projection or mutation functions.
- The Android client ships no privileged Supabase, Cloudflare, R2, GitHub, or emulator credential.
- A failed or invalid refresh preserves the last verified Room snapshot; a failed mutation leaves local state unchanged.
- Library selections remain isolated by listener account and unresolved or unpublished catalog IDs do not enter UI or playback.
- User-visible controls preserve explicit labels, polite status announcements, and 48dp touch targets.

## Quality gates

Acceptance requires the focused Library unit/lint/instrumentation compilation gate, the full Android unit/lint/debug/instrumentation/R8 build, Room migration coverage, database pgTAP/lint/migration replay, manifest/signature/credential checks, and a successful cloud-emulator launch of the authentication flow. Tag and release `v0.3.0` are created only after the candidate APK matches the validated CI artifact.
