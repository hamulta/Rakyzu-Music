# Rakyzu Music Android 0.2.2

## Scope

- Added a typed Search-to-artist-detail destination with explicit Back navigation.
- Preserved the listener's Search query and selected Search destination across detail navigation.
- Derived artist data entirely from the observed offline-first Room catalog using exact artist IDs.
- Ordered releases newest-first with stable title and ID tie-breakers.
- Built a deterministic artist track queue ordered by release, disc, track number, title, and ID.
- Added Play all and accessible per-track playback actions using the complete artist queue.
- Added explicit loading, unavailable-artist, and empty-discography states.
- Added four artist-detail unit tests, two navigation unit tests, and five Compose accessibility/interaction regressions.

## Security and privacy

- Artist, album, and track associations use canonical catalog IDs rather than display-name inference.
- Artist detail reads the existing local catalog and issues no network, Supabase, Worker, or R2 request.
- Search query restoration remains bounded to Android saved UI state and is not copied into the artist route.
- Artist IDs and catalog metadata are not added to logs, diagnostics, analytics, or telemetry.
- No database migration, Worker deployment, Supabase policy, R2 object, Room schema, Android permission, or privileged client credential was added.
- Existing encrypted sessions, Supabase RLS, authenticated private media delivery, and cleartext-traffic rejection remain unchanged.

## Quality gates

The release is accepted only after 111 Android unit tests, Android lint with zero errors and no new warnings, focused Home and Search unit/lint/instrumentation-APK validation, debug APK assembly, all debug test APK assemblies, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. Instrumentation tests are compiled into their AndroidTest APKs; no emulator execution is claimed. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.2.2`.
