# Rakyzu Music Android 0.0.10

## Scope

- Added an exact allowlist parser for password-recovery callbacks covering scheme, raw authority, path, query count/name, bounded decoded code, control characters, and fragments.
- Added `singleTop` callback delivery and identical cold-start/`onNewIntent` handling so an active Rakyzu Music task processes valid recovery links without duplicate activities.
- Explicitly disabled cleartext traffic in both the application manifest and Android network security configuration.
- Replaced the permanent playback progress loop with a lifecycle-aware sampler that exists only while audio is actively playing and cannot start duplicate jobs.
- Reused immutable queue snapshots during progress updates and rebuilt queue metadata only when the Media3 timeline or item count changes.
- Added unit coverage for malicious/malformed callback variants, sampler start/stop behavior, duplicate-job prevention, and queue-cache invalidation.
- Pinned every reusable action in Android CI to a verified full-length commit SHA.
- Added minified and resource-shrunk `assembleRelease` execution to local and CI quality gates so R8 regressions are detected before publication.

## Security and performance review

- No privileged Supabase, Cloudflare, or R2 credential is accepted by Android configuration or stored in source, media metadata, queue state, or release artifacts.
- Callback input changes local recovery state only after the full branded URI contract passes; Supabase authentication state remains authoritative.
- All Android application networking is HTTPS-only, while authenticated media requests continue to resolve bearer state just in time.
- Static playback performs no periodic progress wake-up, and large queues are not remapped on each 500 ms progress sample.
- CI actions are immutable and the release optimizer is exercised on every Android push and pull request.

## Quality gates

The release is accepted only after callback, playback, repository, ViewModel, and navigation unit tests; all Android unit tests; Android lint; debug APK assembly; debug test APK assembly; minified R8 release assembly; merged-manifest verification; secret scanning; and GitHub Actions pass. The branded GitHub artifact and release asset must match this document before tagging `v0.0.10`.
