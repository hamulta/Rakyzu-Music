# Rakyzu Music Android 0.8.8.1

This Android authentication-experience hotfix uses application ID `my.id.rakyzumusic`,
versionName `0.8.8.1`, versionCode `107`, min SDK 26, target/compile SDK 37, and the unchanged Room
schema 12. Android requires an integer versionCode, so the four-part public release version is
represented by versionName/tag/artifact `0.8.8.1` and the monotonically increasing code `107`.

## Branded authentication experience

- Adds an animated first-run Welcome screen with responsive layout and a functional Get Started
  action. Sign In can navigate back to it, while sign-out returns directly to Sign In.
- Adds the interactive Sign In gateway with Rakyzu, Google, Facebook, and Apple branding, native
  Google authentication, Supabase Facebook OAuth, password Log In, and Sign Up entry points.
- Rebuilds Log In and Sign Up with the same branded visual language, scroll-safe layouts, 48 dp
  interaction targets, visible field labels, password visibility, validation, loading, and errors.
- Keeps Remember Me only on Log In, adds Confirm Password only where required, and provides the
  requested cross-links and back navigation on both forms.
- Keeps Apple intentionally non-authenticating for this release and displays the approved
  availability message instead of starting a fake or incomplete OAuth flow.
- Applies the Rakyzu mark to the Android launcher icon and all authentication screens.

## Session, recovery, and legal behavior

- Remember Me controls encrypted session persistence without weakening server authentication.
- Forgot-password links continue into the dedicated New Password flow; confirmation callbacks
  continue through the existing secure Supabase callback boundary.
- Google uses Android Credential Manager with a nonce-bound ID token; Facebook uses the configured
  Supabase provider. No provider secret or privileged Supabase/Cloudflare credential is shipped.
- Adds detailed public Privacy Policy, Terms of Service, and Data Deletion pages with responsive,
  accessible markup, strict security headers, and GET/HEAD-only routing.
