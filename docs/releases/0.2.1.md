# Rakyzu Music Android 0.2.1

## Scope

- Moved Search state ownership to the authenticated listener shell so a query survives top-level tab navigation.
- Added a bounded `SavedStateHandle` query contract for Android Activity and process recreation.
- Restored the saved query before the first Room catalog emission and recomputed results from the canonical local catalog.
- Added automatic field focus when Search enters composition and a dedicated IME Search action.
- Dismissed focus and the software keyboard after IME submission while keeping results visible.
- Made Clear return focus to the empty search field for immediate follow-up input.
- Added two SavedState unit tests and two Compose focus/IME accessibility regressions.

## Security and privacy

- Search saves at most 100 query characters in Android UI saved state for restoration; it does not persist result data.
- Query text is never logged, sent to Supabase or the Worker, included in diagnostics, or used for telemetry.
- Search state remains keyed by authenticated listener ID, and no query is copied into playback metadata or media requests.
- No database migration, Worker deployment, Supabase policy, R2 object, Room schema, Android permission, or telemetry was added.
- Existing encrypted sessions, Supabase RLS, authenticated private media delivery, and cleartext-traffic rejection remain unchanged.

## Quality gates

The release is accepted only after 105 Android unit tests, Android lint with zero errors and no new warnings, focused Home and Search unit/lint/instrumentation-APK validation, debug APK assembly, all debug test APK assemblies, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. Instrumentation tests are compiled into their AndroidTest APKs; no emulator execution is claimed. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.2.1`.
