# Rakyzu Music Android 0.1.7

## Scope

- Added authenticated album artwork loading to featured, recently played, new-release, and complete-catalog Home cards.
- Added a process-wide Coil 3 image loader with crossfades, a bounded 25% memory cache, and a 128 MiB disk cache.
- Added distinct placeholder, loading, loaded, and failure visuals without duplicating TalkBack descriptions.
- Added the authenticated `GET`/`HEAD /v1/albums/{uuid}/artwork` Worker route backed by private R2.
- Added album-level JWT and Supabase RLS authorization before any R2 lookup.
- Added private 24-hour cache control, ETag delivery, and `If-None-Match` support.
- Added deterministic coverage for Android request construction/redaction, artwork state mapping/cache keys, Compose fallback states, Worker authorization, MIME filtering, cache headers, and conditional requests.

## Security and privacy

- Android sends the current Supabase access token only in the artwork request's in-memory `Authorization` header.
- Request diagnostics redact authorization; cache keys contain only normalized album UUIDs.
- The Worker verifies the listener JWT and re-evaluates album visibility through Supabase RLS before deriving the private R2 key.
- The app receives neither R2 credentials nor a direct R2 object URL; artwork is returned only through the Rakyzu API boundary.
- Artwork objects are limited to AVIF, JPEG, PNG, and WebP metadata and use private rather than shared cache semantics.
- No dangerous Android permission, database migration, or Room schema change was added.
