# Rakyzu Music Android 0.1.5

## Scope

- Moved featured-queue and new-release derivation from the Home composable into the state-holder boundary.
- Reused canonical catalog, listening-history, and derived-section references when Room emits structurally equal snapshots.
- Rebuilt derived sections only when catalog content actually changes, while preserving deterministic release-date ordering.
- Stabilized featured playback callbacks, filter data, and per-track action/subtitle strings across unrelated recompositions.
- Narrowed the catalog-status composable to scalar inputs so status-only updates do not invalidate the full Home state boundary.
- Added unit coverage for reference reuse, recently-played-only updates, changed-catalog derivation, release ordering, and metadata labels.

## Security and privacy

- This patch adds no permission, endpoint, persistence field, analytics event, or user-data collection.
- Reference canonicalization and section derivation operate only on already authorized in-memory catalog data.
- Existing Supabase RLS, encrypted session storage, private R2 delivery, and account-isolated listening history remain unchanged.

## Quality gates

The release is accepted only after all Android unit tests, Android lint, debug APK assembly, Compose instrumentation APK compilation, all debug test APK assemblies, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.1.5`.
