# Rakyzu Music Android 0.1.1

## Scope

- Added an explicit successful-empty Home state when no published tracks are available.
- Suppressed filters and hero playback controls until the feed contains playable tracks.
- Added one clear refresh action to the empty state.
- Announced loading, degraded, and empty status changes through polite accessibility live regions.
- Removed the inactive notifications control so assistive technology no longer exposes a non-functional action.
- Kept cached playable content visible when refresh fails and prevented overlapping refresh requests.
- Added unit coverage for successful-empty state derivation, cached failure behavior, and duplicate refresh protection.

- Room schema: `2` (unchanged)

- Media API component version: `0.0.7` (unchanged)

## Security and privacy

- This patch adds no new permission, remote endpoint, persistence field, or user-data collection.
- The empty and degraded states expose only bounded product copy and never display raw backend errors.
- Existing Supabase RLS, encrypted session storage, private R2 delivery, and account-isolated listening history remain unchanged.

## Quality gates

The release is accepted only after all Android unit tests, Android lint, debug APK assembly, debug test APK assembly, minified R8 release assembly, manifest and signature verification, credential scanning, and final GitHub Actions success. The published GitHub Release asset must exactly match the verified CI artifact before tagging `v0.1.1`.
