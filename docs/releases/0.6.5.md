# Rakyzu Music Android 0.6.5

This cumulative `0.6.0`–`0.6.5` prerelease uses application ID `my.id.rakyzumusic`,
versionName `0.6.5`, and versionCode `83`.

## Listener experience

- Albums and playlists expose an explicit Download action with track-level progress.
- Transfers wait for Wi-Fi by default; listeners can explicitly allow mobile data in Library.
- Library shows encrypted storage use, available device space, and clear-all controls.
- Every transfer can be paused, resumed, cancelled, or retried and survives process recreation.
- Completed, valid downloads resolve before network streaming in Media3.

## Security and delivery

- `GET /v1/tracks/{uuid}/download` requires a valid listener JWT, rechecks catalog visibility
  through Supabase RLS, derives the private R2 object server-side, and issues a bounded license.
- Android never persists bearer tokens, R2 object keys, direct object URLs, or Cloudflare/S3
  credentials with a download.
- Audio is encrypted at rest with AES-256-GCM and an account-derived non-exportable Android
  Keystore key. Room stores only an opaque file token and bounded delivery metadata.
- A one-gigabyte free-space reserve prevents downloads from exhausting device storage.

## Engineering

- Room schema 9 stores account-scoped transfer state and the listener's mobile-data choice.
- WorkManager enforces persisted network/storage constraints and exponential retry after process
  death.
- The remaining `0.6.6`–`0.6.10` train covers revision reconciliation, explicit sign-out
  retention policy, adaptive/TalkBack hardening, diagnostics/concurrency, and the final offline
  release gate.

Validation and publication evidence is recorded in `docs/WORK_SESSION.md`.
