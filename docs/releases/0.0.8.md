# Rakyzu Music Android 0.0.8

## Scope

- Added the `core:playback` module using AndroidX Media3 `1.11.0`, ExoPlayer, `MediaSession`, and `MediaSessionService`.
- Added background playback ownership with automatic MediaStyle notification and system transport controls.
- Added music audio-focus management and automatic pause when headphones or another private output disconnects.
- Converted catalog tracks into internal UUID-only media items with Rakyzu title, artist, and album metadata.
- Added just-in-time authenticated request resolution so the active Supabase bearer session enters only the HTTPS Worker request header, never the media URI, metadata, notification, logs, or persisted state.
- Rejected malformed media identifiers, non-HTTPS delivery targets, missing bearer headers, and untrusted external media controllers.
- Connected Home catalog cards and the featured play action to the playback session.
- Replaced the static compact-player placeholder with live MediaSession state and a functional play/pause control.
- Cleared playback when the listener is no longer signed in so one account cannot leave audio active across an authentication boundary.

## Security and content boundary

- The APK contains no Supabase privileged key, Cloudflare credential, R2 S3 credential, media object key, or bundled protected audio.
- Only canonical `rakyzu://tracks/{uuid}` items reach the resolver; the existing Android repository and Worker independently validate the UUID again.
- Resolved delivery requests must use HTTPS and a non-empty bearer header. Request string representations redact all headers.
- The exported MediaSession service is required for system discovery but returns a session only to the Rakyzu Music package or a system-trusted controller.
- The private R2 media bucket intentionally remains empty until rights-cleared Rakyzu Music audio is supplied. Missing media degrades to bounded playback failure instead of exposing storage details.
