# Rakyzu Music Android 0.2.10

## Batched scope

This cumulative release delivers milestones `0.2.9` and `0.2.10` in one validated artifact, pipeline, tag, and release. No separate `0.2.9` artifact or tag is published.

- `0.2.9`: added privacy-safe, process-local Search diagnostics for bucketed catalog/result shapes, connectivity, local duration, and remote lifecycle outcomes; cached normalized catalog candidates per Room snapshot; and selected deterministic top-50 results with bounded heaps instead of sorting every match on every keystroke.
- `0.2.10`: added final Search regression contracts for repeated 10,000-track queries, deterministic ranking/totals, pagination eligibility, saved-result resilience, diagnostic privacy/failure isolation, and compiled Compose accessibility states for loading, failure/retry, and duplicate-resistant pagination.

## Security and privacy

- Typing remains local; only explicit submission sends the bounded query through the authenticated Supabase session.
- Diagnostic event types cannot contain query text, listener/catalog IDs, titles, offsets, URLs, tokens, raw exceptions, or backend payloads.
- Counts and durations use fixed coarse buckets; remote events expose only fixed triggers, initial/additional page classes, booleans, and bounded failure enums.
- Diagnostics stay in a process-local 32-event FIFO with a hard 64-event ceiling and 240-character log-line limit; sink or log transport failure cannot alter Search behavior.
- Recent searches remain disabled by default, listener-isolated, capped at ten, and encrypted with a dedicated Android Keystore AES-GCM key when explicitly enabled.
- No privileged Supabase, Cloudflare, R2, or GitHub credential enters the APK or tracked source.

The cumulative release is accepted only after all 145 Android unit tests pass, the focused Search lint and complete Android lint suites report zero errors, all Search instrumentation tests compile into the AndroidTest APK, debug and all instrumentation APKs assemble, the minified/resource-shrunk R8 release assembles, manifest/signature and credential scans pass, and GitHub Actions succeeds. No emulator execution is claimed. The candidate release asset must exactly match the verified CI artifact before creating tag and release `v0.2.10`.
