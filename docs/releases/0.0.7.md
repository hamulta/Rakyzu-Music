# Rakyzu Music Android 0.0.7

## Scope

- Added the `services/rakyzu-api` Cloudflare Worker with a versioned health endpoint and authenticated track streaming contract.
- Added local Supabase ES256 JWT verification through project JWKS with fixed issuer, audience, authenticated role, and UUID subject validation.
- Reused the listener bearer session against Supabase PostgREST so published-only track RLS is authoritative before media access.
- Added a private `rakyzu-music-media` R2 binding with server-derived object keys; client-provided storage paths are not accepted.
- Added streaming `GET`, metadata-only `HEAD`, bounded/open/suffix byte ranges, `206`, and `416` behavior without buffering media in Worker memory.
- Added strict browser-origin handling, no-store responses, request IDs, security headers, bounded errors, and fail-closed service behavior.
- Deployed the Worker at `https://api.rakyzu.my.id` and added path-filtered GitHub Actions verification and deployment.
- Added an Android media-delivery repository that validates the API origin and track UUID, reads only the active in-memory access token, uses an authorization header, and redacts the token from its string representation.

## Security boundary

- Android contains only public Supabase configuration and the public Rakyzu API origin. Supabase privileged keys, Cloudflare tokens, and R2 S3 credentials remain outside the APK and Worker source.
- The Worker uses an R2 binding rather than S3 credentials and maps each validated track UUID to `media/tracks/{uuid}/source.mp3`.
- A valid JWT alone is insufficient: the matching track must also remain visible through authenticated catalog RLS.
- Untrusted browser origins are rejected before authentication, while native Android requests without an `Origin` header are supported.
- Real media assets are intentionally not bundled or synthesized for this release; the private delivery path returns a bounded media-not-found response until rights-cleared audio is uploaded.

## Quality gates

The release is accepted only after Worker type checks, 18 Worker unit tests, generated-binding drift checks, dry-run and production deployment, production health/auth/CORS probes, Android unit tests, Android lint, debug APK assembly, debug test APK assembly, and both GitHub Actions workflows pass. The branded GitHub artifact and release asset must match this document before tagging `v0.0.7`.
