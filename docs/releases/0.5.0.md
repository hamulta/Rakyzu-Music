# Rakyzu Music Android 0.5.0

Account-scoped Queue foundation and authentication recovery correction, versionCode 46.

## Queue foundation

- Media3 timeline edits and active-item transitions persist deterministic queue order and index
  into Room.
- The initial empty Media3 controller connection cannot erase a previously persisted queue.
- Queue rows and state are keyed by listener account and replaced atomically in one transaction.
- Queue input is bounded and validates identifiers, labels, durations, and active indices before
  any local write.
- Playback exposes bounded add-next, append, move, and remove primitives; UI entry points remain
  scheduled for `0.5.1` and complete TalkBack editing controls for `0.5.2`.
- Process-death restoration is intentionally not claimed before its `0.5.3` acceptance gate.

## Fixes

- Signup now supplies the exact branded confirmation redirect. A valid confirmation callback
  imports or exchanges its Supabase session and continues through the authenticated Home gate.
- Password-recovery deep links import or exchange the Supabase recovery session before the
  New Password panel is shown.
- Both PKCE `code` callbacks and bounded legacy implicit confirmation/recovery fragments are
  supported.
- Callback validation rejects unexpected origins, paths, parameters, types, duplicates,
  missing tokens, control characters and oversized payloads.
- Confirmation and recovery callback types cannot be used on each other's path, and processed
  callback data is cleared from the Activity intent to prevent duplicate exchange or retention.
- Confirm Email remains enabled and live Auth configuration confirms Resend Custom SMTP for the
  Rakyzu Music domain.

## Operational boundary

Custom SMTP credentials remain only in Supabase's managed secret store. Confirmation, recovery,
delivery monitoring, bounce handling, and abuse controls remain release gates before Rakyzu
Music 1.0.0. No SMTP, privileged Supabase, or other service credential is shipped in Android or
committed to this repository.

Per the CEO's final acceptance instruction, this release does not use Appetize or ADB. Automated
callback/parser/UI-state tests, manifest inspection, configured builds, and live service checks
are the acceptance evidence; a physical link-tap runtime claim is intentionally not made.
