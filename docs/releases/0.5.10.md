# Rakyzu Music Android 0.5.10

This cumulative `0.5.6`–`0.5.10` Queue/playback release uses versionCode 56.

## Listener changes

- Account settings now persist separate Low, Standard, or High streaming quality for Wi-Fi and
  mobile data. Data Saver forces Low on Android-metered networks.
- Playback interruptions caused by retryable delivery failures keep the listener's explicit
  queue. Now Playing offers a bounded retry and connectivity recovery uses that same path.
- Queue rows stack their controls on compact widths or at 1.3x font scale, allow two-line
  metadata, retain 48dp actions, and announce current/queued state to TalkBack.

## Engineering and privacy

- Media3 resolves quality immediately before opening the stream. The authenticated Worker accepts
  only `low`, `standard`, or `high`, then maps the choice to the matching private R2 media object.
- Playback diagnostics use only fixed failure categories, coarse Queue-size buckets, and retry
  ordinals. They contain no listener/catalog IDs, labels, URLs, authorization values, payloads,
  raw exceptions, or persistent analytics upload.
- Recommendations remain outside the Queue: recovery never adds or substitutes media.

## Honest limitations

- Low and High playback require the rights-cleared `source-low.mp3` and `source-high.mp3` objects
  for that track. A missing selected variant returns unavailable rather than silently using a
  different quality.
- Downloads/offline media, remote device control, lossless audio, subscriptions, production
  signing, and Play Store delivery remain future milestones. A minified unsigned release APK is
  validation evidence only; the distributed debug APK is not a production-signed Play artifact.
- Spotify's public audio-quality behavior informed the product concept. Rakyzu Music uses original
  code, labels, infrastructure, catalog policy, and assets.
